# Changes — 01-04-26

## 1. Build error: HidSharp `Indexes` not iterable (CS1579)

**File:** `src/SvalboardLayerViz.Core/Device/DeviceConnectionService.cs`

`DeviceConnectionService.FindVialDevices()` used `foreach` over `deviceItem.Usages`, but HidSharp 2.6.4's `Indexes` type doesn't implement `IEnumerable`. It also called nonexistent methods `.GetUsagePage()` and `.GetUsage()`.

**Fix:** Replaced the inner loop with `Indexes.ContainsValue()` using packed 32-bit HID usage values (`(usagePage << 16) | usageId`).

## 2. Retargeted from .NET 8 to .NET 10

**Files:** All three `.csproj` files

The machine only has .NET 10 installed. Changed `<TargetFramework>net8.0</TargetFramework>` to `net10.0` in Core, App, and Tests projects.

## 3. Connection timeout: missing HID report ID byte

**File:** `src/SvalboardLayerViz.Core/Protocol/VialProtocolService.cs`

`SendCommand()` wrote raw 32-byte buffers, but HidSharp requires a report ID byte (0x00) prepended to writes. The device never received valid commands, causing read timeouts.

**Fix:** Write buffer now uses `device.GetMaxOutputReportLength()` (33 bytes) with report ID as byte 0. Read buffer uses `GetMaxInputReportLength()` and skips the report ID byte in responses.

## 4. XZ decompression failure: wrong block size in `GetDefinition()`

**File:** `src/SvalboardLayerViz.Core/Protocol/VialProtocolService.cs`

`GetDefinition()` copied only `PayloadSize` (28) bytes per block, but definition responses use the full 32-byte report as data (no header). This corrupted the downloaded XZ payload.

**Fix:** Changed `PayloadSize` to `ReportSize - dataOffset` so all 32 data bytes are copied per block.

## 5. XAML crash: unresolvable type cast in DataTemplate binding

**File:** `src/SvalboardLayerViz.App/Views/MainWindow.axaml`

The layer tab buttons used `$parent[Window].((vm:MainWindowViewModel)DataContext).SelectLayerCommand` which failed at runtime — Avalonia 11's compiled bindings can't resolve the type cast inside a DataTemplate.

**Fix:** Added a `SelectCommand` directly on `LayerViewModel` (with an `Action<int>` callback to the parent VM) and bound the button to `{Binding SelectCommand}`. Eliminated the cross-DataContext type cast entirely.

**File:** `src/SvalboardLayerViz.App/ViewModels/LayerViewModel.cs` — added `Select()` relay command and constructor callback parameter.

## Phase 3: Keycode Fixes, Color System & Test Coverage

### 11. Fixed ALL layer keycode ranges (critical bug)

**File:** `src/SvalboardLayerViz.Core/Keymap/KeycodeService.cs`

All 6 layer function keycode ranges (MO, TG, DF, TO, TT, OSL) were using old pre-2023 QMK values. The Svalboard firmware and keybard-ng use the post-2023 QMK layout. Every layer function key was being incorrectly resolved.

**Fix:** Updated all 12 constants to match keybard-ng's `keygen.ts`:
- TO: 0x5200–0x521F, MO: 0x5220–0x523F, DF: 0x5240–0x525F
- TG: 0x5260–0x527F, OSL: 0x5280–0x529F, TT: 0x52C0–0x52DF

Added OSL resolution block (previously collided with TO) and one-shot modifier (OSM) handler at 0x52A0–0x52BF.

### 12. Expanded keycode coverage

**File:** `src/SvalboardLayerViz.Core/Keymap/KeycodeService.cs`

Added ~35 new BasicKeycodes entries: numpad keys (0x53–0x63), F13–F24 (0x68–0x73), media keys (Mute/Vol+/Vol-), App key (0x65), non-US hash (0x32).

Added three new keycode range handlers:
- **Mod-Tap** (0x2000–0x3FFF): `MT(mod, kc)` — modifier on hold, key on tap
- **Layer-Tap** (0x4000–0x4FFF): `LT(layer, kc)` — layer on hold, key on tap
- **Layer-Mod** (0x5000–0x51FF): `LM(layer, mod)` — layer + modifier combo

### 13. Custom keycode resolution

### 23. Custom keycode base address fix (critical bug)

**File:** `src/SvalboardLayerViz.Core/Keymap/KeycodeService.cs`

Custom keycodes were resolved starting at `QK_USER` (0x7E40), but Vial's keyboard definition maps custom keycodes starting at `QK_KB` (0x7E00). This meant all 20 Svalboard-specific keycodes (DPI controls, scroll toggles, sniper modes, automouse toggle, etc.) were being misinterpreted as modifier+key combinations — e.g., 0x7E11 ("SV_OUTPUT_STATUS") was showing as "N" with phantom modifiers.

**Fix:** Changed base from `QK_USER` (0x7E40) to `QK_KB` (0x7E00). Updated fallback label from `USER{n}` to `KB{n}`.

### 24. Layer selection bug after empty-layer filtering

**File:** `src/SvalboardLayerViz.App/ViewModels/MainWindowViewModel.cs`

After adding empty-layer filtering (item 21), clicking layer tabs for higher-numbered layers showed no keys. `SelectedLayer` used `Layers.ElementAtOrDefault(index)` which looks up by position in the filtered collection, but layer tabs pass their actual layer index (e.g., 14). Changed to `Layers.FirstOrDefault(l => l.Index == SelectedLayerIndex)`.

### 25. LT with KC_NO display

**File:** `src/SvalboardLayerViz.Core/Keymap/KeycodeService.cs`

`LT(14, KC_NO)` — a layer-tap where hold activates a layer but tap does nothing — was displaying "0x00" as the primary label with "LT(14)" as secondary. Now shows "LT(14)" as the primary label when the tap key is KC_NO.
