# Changes — 04-04-26 (Session 7)

## Shared Board Layout — Single Source of Truth for Export & UI

### 71. BoardLayoutComputer — shared layout computation in Core

**New file:** `src/SvalboardLayerViz.Core/Layout/BoardLayoutComputer.cs`

- Static class that computes complete board layout from a `Layer` model
- Splits keys into left/right hand via `SvalboardLayout.IsRightHand(row)`
- Groups keys by row, names clusters via position lookup
- Identifies thumb clusters: row 0 (left hand = L-Mod), row 5 (right hand = L-Thumb/R-Thumb)
- Computes board-absolute pixel positions: `key.X * Scale`, `key.Y * Scale`
- Computes cluster and hand bounding boxes
- Exposes `BottomClusters` set (L-Thumb, R-Thumb, L-Mod) for hide-thumb export
- `GetBoardHeightExcludingBottomClusters()` for compact export mode
- Returns `ComputedBoardLayout` record consumed by both export and UI

### 72. ComputedBoardLayout — shared layout model records

**New file:** `src/SvalboardLayerViz.Core/Layout/ComputedBoardLayout.cs`

- `PositionedKey(Key, BoardX, BoardY, Width, Height)` — key with board-absolute pixel coords
- `PositionedCluster(Name, IsThumb, Keys, Left, Top, Width, Height)` — cluster with bounding box
- `PositionedHand(ThumbCluster?, FingerClusters, AllKeys, Width, Height)` — one hand's layout
- `ComputedBoardLayout(LeftHand, RightHand, AllKeys)` — complete board for one layer
- All records are immutable, no UI dependencies — lives in Core

### 73. BoardRenderer refactored to use BoardLayoutComputer

**Modified:** `src/SvalboardLayerViz.Core/Export/BoardRenderer.cs`

- `RenderLayer()` now calls `BoardLayoutComputer.Compute(layer)` and traverses hands → clusters → keys
- Added `RenderHand()` and `RenderCluster()` helper methods for structured traversal
- `RenderKey()` takes `PositionedKey` instead of raw `Key`, uses `posKey.BoardX/BoardY`
- Removed inline `key.X * Scale` positioning, `_positionLookup` dictionary, `BottomClusters` set, and `IsThumbKey()` method — all moved to `BoardLayoutComputer`
- `GetLayerBlockHeight()` delegates to `BoardLayoutComputer.GetBoardHeightExcludingBottomClusters()`

### 74. ViewModels refactored to consume BoardLayoutComputer output

**Modified:** `HandViewModel.cs`, `KeyClusterViewModel.cs`, `KeyViewModel.cs`, `LayerViewModel.cs`

- **LayerViewModel:** Replaced manual key splitting with `BoardLayoutComputer.Compute(layer)`, passes `PositionedHand` to `HandViewModel`
- **HandViewModel:** Constructor takes `PositionedHand` instead of raw key list. Computes `handOriginPx` for hand-relative positioning. Wraps each `PositionedCluster` in `KeyClusterViewModel`. Removed all `SvalboardLayout.GetKeyPositions()` lookup and grouping logic
- **KeyClusterViewModel:** Constructor takes `PositionedCluster` + `handOriginPx`. Computes hand-relative position: `Left = cluster.Left - handOriginPx`. Creates `KeyViewModel` with cluster origin for cluster-relative coords
- **KeyViewModel:** Constructor takes `PositionedKey` + cluster origin offsets. Position stored directly as `Left = posKey.BoardX - clusterOriginX` (pixels). Width/Height from `PositionedKey` (already in pixels)

### 76. Stacked view right margin fix

**Modified:** `src/SvalboardLayerViz.App/ViewModels/MainWindowViewModel.cs`

### 77. Unstacked view left margin fix

**Modified:** `src/SvalboardLayerViz.App/Views/BoardView.axaml`, `MainWindowViewModel.cs`

- Removed explicit `Width`/`Height` bindings from Border wrappers around HandView in BoardView.axaml
- Borders now size to their HandView content instead of using `HandContainerWidth`/`HandContainerHeight`
- Removed unused `HandContainerWidth` and `HandContainerHeight` properties from MainWindowViewModel
- Root cause: `HandContainerWidth = (HandWidth + 1.0) * Scale = 768px` but `HandViewModel.Width = 708px`, creating a 60px mismatch that offset the inner Canvas
