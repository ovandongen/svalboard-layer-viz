## LED-Based Active Layer Detection

### 104. Svalboard custom sub-protocol: per-layer color read

**New/Modified:** `src/SvalboardLayerViz.Core/Protocol/VialCommands.cs`, `src/SvalboardLayerViz.Core/Protocol/VialProtocolService.cs`, `src/SvalboardLayerViz.Core/Protocol/IVialProtocolService.cs`

- Added Svalboard custom sub-protocol constants (`SvalPrefix = 0xEE`, `SvalGetProtoVersion = 0x01`, `SvalLayerColorGet = 0x10`)
- `GetSvalProtoVersion()` sends `[0xEE, 0x01]` and validates the ASCII "sval" handshake + u32 LE proto version. Returns null on unsupported firmware
- `GetLayerColor(layer)` sends `[0xEE, 0x10, layer]` and returns `(H, S, V)`. All-zero response treated as unsupported (V=0 means LED off)
- `GetCurrentLedHueSat()` sends standard VIA `[0x08, 0x83]` (LightingGetValue + QmkRgblightColor) and returns `(H, S)` from the response. Used for LED polling
- Reference: keybard-ng `pages/js/vial/sval.js`, confirmed on Svalboard Lightly firmware (sval proto version 3)

### 105. Per-layer HSV stored on Layer model

**Modified:** `src/SvalboardLayerViz.Core/Keymap/KeymapLoader.cs`

- On connect, probes `GetSvalProtoVersion()` to check firmware capability
- If supported, reads `GetLayerColor(layerIdx)` for each layer and stores the HSV triple on `Layer.ColorHue`, `Layer.ColorSat`, `Layer.ColorVal`
- These values feed into `LayerColorService.GetLayerColors()` as the device color source (middle priority: user hex > device HSV > algorithmic)

### 106. LED polling service

**New file:** `src/SvalboardLayerViz.Core/Protocol/LedPollingService.cs`

- Polls `GetCurrentLedHueSat()` at ~10Hz on a background thread
- Fires `LedColorChanged` event only when hue or saturation actually changes
- Used as a proxy for the active layer: the Svalboard LED color uniquely identifies which layer is active, catching layers the matrix-based heuristic can't observe (e.g. mouse layer, firmware-internal switches)

### 107. LED color → layer resolver

**New file:** `src/SvalboardLayerViz.Core/Keymap/LedColorLayerResolver.cs`

- `Resolve(layers, ledHue, ledSat, currentLayer)` matches polled rgblight H+S against stored per-layer colors within tolerance (±4 hue, ±16 saturation on 0-255 scale)
- Handles collisions: if the current layer is among matches, keeps it (stable behavior). Otherwise picks lowest-index match
- Uses circular distance for hue comparisons (wraps at 255→0)

### 108. Active layer switching via LED polling

## Bug Fix: HID Command Race Condition

### 115. Thread-safe HID command serialization

**Modified:** `src/SvalboardLayerViz.Core/Protocol/VialProtocolService.cs`

- **Root cause:** `MatrixPollingService` and `LedPollingService` both call `SendCommand()` on separate background threads at ~10Hz. Without synchronization, their write→read pairs could interleave: thread A writes a matrix query, thread B writes an LED query before A reads, then A reads B's LED response and interprets the color bytes as matrix state — causing phantom key presses (random flickering on left index/thumb clusters)
- **Fix:** Added `lock (_sendLock)` around the entire write→read pair in `SendCommand()`, guaranteeing each HID command-response exchange is atomic
- This was never an issue before LED polling because only one service (matrix polling) used the HID stream at a time
