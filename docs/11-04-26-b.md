# Changes — 11-04-26 (Session 17)

## Phase 4a Session 11 — Save Pipeline

### 169. SaveResult — discriminated outcome record

**New file:** `src/SvalboardLayerViz.Core/Keymap/SaveResult.cs`

- Abstract `SaveResult(int Applied)` with four sealed cases: `SaveSuccess`, `SaveCancelled`, `SaveAborted(string Reason)`, `SavePartial(int Applied, int StillPending, int Diverged, string FailureMessage, IReadOnlyList<SetKeycodeWrite> Remaining)`
- `StillPending` = device matches the pre-edit baseline (user's intent never landed); `Diverged` = device differs from both baseline and intent (someone else wrote, or a partial write landed in an unexpected state)
- Lets the VM branch on save outcome without sentinel values or boolean tuples

### 170. SaveFlowExecutor — pure Core write loop

**New file:** `src/SvalboardLayerViz.Core/Keymap/SaveFlowExecutor.cs`

- Static `Execute(IVialProtocolService, IReadOnlyList<SetKeycodeWrite>, CancellationToken)` returns `ExecutionOutcome(Applied, FailedAt, Failure, Cancelled)`
- Loops `protocol.SetKeycode(...)` per write, checks `ct.IsCancellationRequested` between iterations, captures any exception in `Failure` instead of propagating
- Logs each call via `DiagnosticLog.Info("Save", ...)` with applied count for traceability
- Pure, no VM coupling — covered by 8 dedicated executor tests

### 171. KeyboardConfig — VID/PID for snapshot identity

**Modified:** `src/SvalboardLayerViz.Core/Models/KeyboardConfig.cs`, `src/SvalboardLayerViz.Core/Keymap/KeymapLoader.cs`

- Added `required int VendorId { get; init; }` and `required int ProductId { get; init; }` to `KeyboardConfig`
- `KeymapLoader.LoadAsync` now populates them from `device.HidDevice.VendorID` / `ProductID`
- Needed because `SnapshotService.CaptureAsync` requires a `KeyboardId(VendorId, ProductId, Uid)` and the Vial UID alone is insufficient for snapshot path identity

### 172. KeymapEditSession — clone helpers for save flow

**Modified:** `src/SvalboardLayerViz.Core/Keymap/KeymapEditSession.cs`

- Added `CloneBaseline()` and `CloneCurrent()` returning `ushort[,,]` copies of the private baseline/current arrays
- Lets the save flow snapshot pre-save device state and the user's intended state without reaching into private fields or rebuilding the keymap from layer view models

### 173. MainWindowViewModel — full save orchestration

**Modified:** `src/SvalboardLayerViz.App/ViewModels/MainWindowViewModel.cs`

- Constructor gains optional `ISnapshotService` parameter (defaults to `new SnapshotService()` writing to `%AppData%/SvalboardLayerViz/snapshots`)
- New observables: `[ObservableProperty] private bool _isSaving;`, `private CancellationTokenSource? _saveCts;`, `private bool _wasLockedOnEnterEdit;`
- New callback seams: `Func<IReadOnlyList<SafetyWarning>, Task<bool>>? ConfirmSafetyWarningsRequested` (null = auto-confirm), `Action<SaveResult>? SaveCompletedCallback`
- `EnterEdit` now captures `_wasLockedOnEnterEdit = !status.Unlocked` immediately after the unlock-status check; cleared in `DiscardEdit` and the disconnect branch of `OnIsConnectedChanged`
- `SaveEditCommand` rewritten from disabled stub to async orchestrator: safety check → optional confirm callback → pre-save snapshot → `Task.Run(SaveFlowExecutor.Execute)` → `ReloadKeymapFromDeviceAsync` → outcome branching → post-save snapshot → background prune → re-lock if originally locked
- `CanSaveEdit() => IsEditMode && DirtyCount > 0 && !IsSaving && KeyboardConfig is not null` with `[NotifyCanExecuteChangedFor]` on the gating properties
- New private helpers: `GetKeyboardId()` (builds `KeyboardId.From(VID, PID, KeyboardId)`), `GetDeviceKeymap()` / `BuildIntendedKeymap()` (clone session arrays), `ReloadKeymapFromDeviceAsync(ct)` (re-runs the keymap fetch step from `TryConnectAsync` without redoing enumeration/LED probing), `BuildPartialResult` (diffs reloaded device state against intent into applied/stillPending/diverged buckets and rebuilds `_editSession` from the new baseline so the user can retry without re-editing), `ApplySaveResult` (per-outcome cleanup and status messaging)
- Re-lock policy mirrors the pre-edit lock state — re-locks only on `SaveSuccess` AND when `_wasLockedOnEnterEdit` was true. Locking failure logs at Warn but does not fail the save
