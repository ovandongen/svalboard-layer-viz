# Changes — 11-04-26 (Session 16)

## Phase 4a Session 10 — Picker MVVM Refactor

### 160. IKeycodeBuilder — observable typed builders interface

**Modified:** `src/SvalboardLayerViz.Core/Keymap/Builders/IKeycodeBuilder.cs`

- Replaced the untyped `ArgumentSlot` / `ArgumentKind` / `Slots` / `SetSlot` / `ClearSlot` API with `INotifyPropertyChanged` and a `Description` property
- Added `KeycodeBuilderBase` abstract class with `Notify(params string[])` helper that fans out to one `PropertyChanged` event per name
- Added `IHasTapKey` marker interface (`ushort? TapKey { get; set; }`) so the picker VM can target ModTap and LayerTap with one `SelectTapKey` command without a type switch
- Removed `ArgumentSlot.HasValue` and the whole boxed-`object` slot model — concrete builders expose typed nullable properties instead

### 161. Concrete builders — observable typed properties

**Modified:** `src/SvalboardLayerViz.Core/Keymap/Builders/{ModTap,OneShotMod,LayerTap,LayerMod,LayerFunction,CustomKeycode}Builder.cs`

- All six builders now derive from `KeycodeBuilderBase` and expose typed nullable backing fields:
  - `ModTapBuilder` — `ModFlags? Mods`, `ushort? TapKey` (implements `IHasTapKey`)
  - `OneShotModBuilder` — `ModFlags? Mods`
  - `LayerTapBuilder` — `int? Layer`, `ushort? TapKey` (implements `IHasTapKey`)
  - `LayerModBuilder` — `int? Layer`, `ModFlags? Mods`
  - `LayerFunctionBuilder` — `LayerFunctionKind? Kind`, `int? Layer`
  - `CustomKeycodeBuilder` — `int? Index`
- Each setter calls `Notify(nameof(<self>), nameof(CanBuild), nameof(PreviewLabel))` so the wizard's Next button and preview label live-update as the user fills slots
- `LayerFunctionBuilder.Kind` setter additionally raises `KindDescription` since the per-function help text is computed from `Kind`

### 162. PickerSessionViewModel — observable-driven state

**Modified:** `src/SvalboardLayerViz.App/ViewModels/PickerSessionViewModel.cs`

- Subscribes to `ActiveBuilder.PropertyChanged` in `OnActiveBuilderChanged`; on any builder property change re-raises `CanGoNext` and `ShowNextButton`. Old subscription is detached when `ActiveBuilder` flips
- Added `SelectedCatalogEntry` observable so basic-key selection routes through a two-way binding (auto-advances to Preview from `OnSelectedCatalogEntryChanged` only when `CurrentStep == Selection`, so hydration paths don't cause spurious step jumps)
- `GoBack` semantics rewritten: Preview→Arguments and Arguments→Selection now preserve `ActiveBuilder`, slot values, and `Result` so re-pressing Next immediately returns to the previous step. Only Selection→Category clears retained state
- `ShowNextButton` upgraded from `CurrentStep == Arguments` to a switch that also returns true on Selection when retained state exists, so the user can rebound forward after Back
- `HydrateWizardStateFrom` rewrite: each descriptor arm becomes direct typed property assignment (e.g. `lf.Kind = layerFn.Kind; lf.Layer = layerFn.Layer; ActiveBuilder = lf;`). ~99 lines of nested null-checks → ~50 lines of straight-line code
- Added `LayerOptions` (`IReadOnlyList<LayerOption>`) for layer-dropdown binding, `LayerFunctionKinds` static enum-values list, `AllBasicKeycodes` flat catalog projection for the Mod-Tap / Layer-Tap key picker
- Added `SelectTapKey(ushort)` relay command — sets `TapKey` on whichever `IHasTapKey` builder is active
- Deleted `NotifyBuilderChanged()` — the old code-behind hack is gone now that builders raise their own change notifications

## Picker localization

### 166. BuilderLocalization — Core/App layering bridge

**New file:** `src/SvalboardLayerViz.Core/Keymap/Builders/BuilderLocalization.cs`

- Static `Func<string, string> Resolve` callback (defaults to `key => key`) lets Core builders read localized display strings without taking a hard reference to App's `Strings.resx` or `ResourceManager`
- All six builder `DisplayName` / `Description` getters now call `BuilderLocalization.Get("Builder_<X>_Name")` / `Get("Builder_<X>_Desc")`

**Modified:** `src/SvalboardLayerViz.App/App.axaml.cs`

- Wired `BuilderLocalization.Resolve = key => Loc.Instance[key];` immediately after `Loc.Instance.SetCulture(initialSettings.Language)` so runtime culture changes propagate to next-opened picker dialog
