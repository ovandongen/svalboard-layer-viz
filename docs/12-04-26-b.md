### 198. HistoryWindowViewModel

**New file:** `src/SvalboardLayerViz.App/ViewModels/HistoryWindowViewModel.cs`

- Constructor takes `ISnapshotService` and `KeyboardId?`. Nullable keyboard id is deliberate: the History view is browsable in read-only mode even when no device is connected. `ListAsync` already accepts a null filter (returns all snapshots across all keyboards on disk), so the open path works fine without a device. Only `ImportAsync` requires a non-null `KeyboardId`; it has an internal null guard that surfaces `History_NoDevice` in the status bar instead of crashing.
- `[ObservableProperty]` surface: `SearchText`, `ShowManual`, `ShowAuto`, `ShowInitial` (all `true` by default), `SelectedRow`, `StatusMessage`. Each filter property's `partial void OnXxxChanged` calls `ApplyFilter()`, which rebuilds `Rows` from the cached `_allRows` list applying chip + search predicates.
- `ApplyFilter` chip rule: a row passes if its `SnapshotReason` is in the enabled set — `Manual` ↔ `ShowManual`; `PreSave` *and* `PostSave` ↔ `ShowAuto`; `FirstConnect` ↔ `ShowInitial`. Search is case-insensitive substring on `DisplayLabel`. Sort: `CapturedAt` descending (newest first) — `LoadAsync` defers ordering to `ISnapshotService.ListAsync`, which already sorts that way.
- Commands:
  - `LoadAsync` / `RefreshAsync` — pull `ListAsync(_keyboardId, ct)`, replace `_allRows`, re-apply filter.
  - `DeleteAsync(row)` — calls `ConfirmDelete` callback, then `_snapshots.DeleteAsync(row.FilePath)`, removes from `_allRows`, re-filters, sets status.
  - `ExportAsync(row)` — calls `RequestExportFilePath(suggestedFilename)`, then `_snapshots.LoadAsync` + `ExportAsync(snapshot, dest)`.
  - `ExportAllAsync` — calls `RequestExportFolderPath`, loops `_allRows`, swallows per-file errors as warnings (don't abort the batch on one bad file).
  - `ImportAsync` — calls `RequestImportFolderPath`, enumerates `snapshot-*.json`, calls `_snapshots.ImportAsync(file, _keyboardId)` per file, aggregates `ImportResult` counts + warnings into a single combined result, fires `ShowImportSummary`, reloads list if anything was actually imported.
  - `OpenDiff(row)` — **S2 stub**: sets `StatusMessage = Loc[History_DiffComingSoon]` and writes a `DiagnosticLog.Info("History", "Diff preview deferred to S3")`. Must not throw or mutate state. S3 wires the real `SnapshotDiffDialog`.
  - `Close` — fires `CloseRequested` callback (App layer wires it to `Window.Close`).
- Pickers + dialogs are exposed as `Func<Task<string?>>` / `Func<string, Task<bool>>` callbacks rather than direct StorageProvider calls. App layer wires the real implementations against `mainWindow.StorageProvider`; tests substitute fakes returning canned paths. Same pattern UnlockDialog already uses for separation of concerns.

### 199. HistoryWindow XAML + code-behind

**New file:** `src/SvalboardLayerViz.App/Views/HistoryWindow.axaml`, `src/SvalboardLayerViz.App/Views/HistoryWindow.axaml.cs`

- 720×520 dialog, `MinWidth=520 MinHeight=360`, `WindowStartupLocation=CenterOwner`, `CanResize=True` (per velvet design — S3's diff preview adapts to window size, so the resize affordance is needed even in S2). Catppuccin-ish dark palette to match the rest of the app.
- Layout (DockPanel root): footer with Import / Export-all / status / Close pinned bottom; header `Title_History` text top; search TextBox + three filter ToggleButtons in a Grid row; ListBox of snapshot rows fills the remaining space.
- Row template: Grid `Cols="Auto,Auto,*,Auto"` — `ReasonIcon` glyph, `FormattedTimestamp` (mono), `DisplayLabel` (ellipsis-trimmed), per-row Export + Delete buttons.
- **Avalonia DataTemplate xmlns gotcha:** the per-row buttons need to invoke commands on the *parent window's* VM, not the `SnapshotRowViewModel` row VM. The first cut used the `(vm:HistoryWindowViewModel)DataContext` cast pattern inside the binding path; the runtime XAML parser cannot resolve namespace prefixes inside deferred-loaded DataTemplate bindings, throws `System.ArgumentException: Unable to resolve type vm:HistoryWindowViewModel` the moment the template instantiates, the dispatcher's UnhandledException handler swallows it, and the user sees "nothing happens" when clicking the History button. **Fix:** name the ListBox (`x:Name="RowsList"`) and use ElementName binding: `Command="{Binding #RowsList.DataContext.ExportCommand}"`. Saved as `feedback_avalonia_datatemplate_cast.md` so this doesn't bite a third time.
