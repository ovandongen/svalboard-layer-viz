## Phase 4b Session 1 — QMK Settings Protocol + Discovery

First session of Phase 4b (QMK firmware settings editing). Wires the protocol layer for discovering, reading, writing, and resetting QMK settings. No UI, no EditOp, no save flow changes yet — those come in S2–S4. Wire format confirmed against Vial firmware source (`vial-qmk/quantum/vial.c`, `qmk_settings.c`) and keybard-ng client (`qmk.service.ts`).

### 218. IVialProtocolService — three new QMK settings methods

**Modified:** `src/SvalboardLayerViz.Core/Protocol/IVialProtocolService.cs`

- Added `IReadOnlyList<ushort> GetQmkSettingsList()` — paginated discovery via `[0xFE, 0x09]`.
- Added `void SetQmkSetting(ushort settingId, ushort value)` — writes via `[0xFE, 0x0B]`, throws on non-zero status.
- Added `void ResetQmkSettings()` — resets all settings to firmware defaults via `[0xFE, 0x0C]`.
- All synchronous, matching the existing protocol method pattern.

### 219. VialProtocolService — protocol implementations

**Modified:** `src/SvalboardLayerViz.Core/Protocol/VialProtocolService.cs`

- `GetQmkSettingsList()`: paginated query — sends `[0xFE, 0x09, offset_lo, offset_hi]` starting at offset 0. Reads up to 16 u16 LE entries per 32-byte response. Terminates on `0xFFFF` (fill byte). Next page uses last-seen ID as offset. Catches exceptions and returns empty list if firmware doesn't support QMK settings.
- `SetQmkSetting()`: sends `[0xFE, 0x0B, id_lo, id_hi, val_lo, val_hi]`. Checks response byte 0 — throws `InvalidOperationException` on non-zero status.
- `ResetQmkSettings()`: sends `[0xFE, 0x0C]`, fire-and-forget.
