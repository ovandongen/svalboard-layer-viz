# Changes — 12-04-26-e (Phase 4b Session 2 — Core model + catalog + EditOp for QMK settings)

## QMK settings Core infrastructure

Builds the model layer, catalog, edit operations, and save pipeline support for QMK firmware settings editing. No UI in this session — that's S3.

### 225. QmkSettingType enum + QmkSettingDescriptor record

**New file:** `src/SvalboardLayerViz.Core/QmkSettings/QmkSettingType.cs`
**New file:** `src/SvalboardLayerViz.Core/QmkSettings/QmkSettingDescriptor.cs`

- `QmkSettingType` enum: `Boolean`, `UInt8`, `UInt16`, `Enum` — drives UI control selection in S3
- `QmkSettingDescriptor` record: catalog entry with `Id`, `NameKey`, `GroupKey`, `Type`, `Min`, `Max`, `DefaultValue`
- Deliberately separate from `QmkSettingValue` (live state on `KeyboardConfig`) — catalog is static metadata, not device state

### 226. QmkSettingsCatalog

**New file:** `src/SvalboardLayerViz.Core/QmkSettings/QmkSettingsCatalog.cs`

- Static class mirroring `KeycodeCatalog` pattern: grouped `IReadOnlyList<QmkSettingDescriptor>`, lazy `Dictionary<ushort, QmkSettingDescriptor>` lookup
- Five groups: TapHold, OneShot, Combos, AutoShift, Misc
- Only tapping term (`0x0007`) is firmware-confirmed; empty groups for the rest pending device verification
- `GetOrFallback(ushort id)` returns a generic UInt16 descriptor for any ID the firmware exposes but the catalog doesn't know — ensures unknown settings degrade gracefully instead of crashing
