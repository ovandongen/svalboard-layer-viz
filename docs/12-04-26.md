### 191. KeymapSnapshot — UserLabel field + CurrentSchemaVersion constant

**Modified:** `src/SvalboardLayerViz.Core/History/KeymapSnapshot.cs`

- New `public const int CurrentSchemaVersion = 1` — single source of truth for schema version checks (Import uses it to refuse future-format files). The instance `SchemaVersion` initializer now points at the constant instead of a magic `1`.
- New `public string? UserLabel { get; init; }` — optional, defaults to `null`. Will be populated for `SnapshotReason.Manual` snapshots so users can attach a memo like "before refactor". Schema-version-safe: old JSON files (no `userLabel` key) deserialize cleanly because the field is nullable and not `required`. No `[JsonPropertyName]` attribute needed — `SnapshotService.JsonOptions` already sets `PropertyNamingPolicy = JsonNamingPolicy.CamelCase`.
- `SnapshotMetadata` is intentionally NOT extended yet — that's an S2 concern when the History list needs to surface the label per row.

### 193. ISnapshotService.ImportAsync + CaptureAsync userLabel parameter

**Modified:** `src/SvalboardLayerViz.Core/History/ISnapshotService.cs`, `src/SvalboardLayerViz.Core/History/SnapshotService.cs`

- New interface method:
  ```csharp
  Task<ImportResult> ImportAsync(
      string sourceFilePath,
      KeyboardId expectedKeyboard,
      CancellationToken ct = default);
  ```
- `CaptureAsync` gains an optional `string? userLabel = null` parameter, threaded straight into the constructed `KeymapSnapshot.UserLabel` before serialization. Picked over a post-capture `LoadAsync`/`ExportAsync` rewrite because it's a one-line change with minimal blast radius — labels fundamentally belong in the capture call, not as a TOCTOU-prone post-hoc edit.
- `SnapshotService.ImportAsync` decision flow, per velvet plan §1193 rules:
  1. Read + deserialize via the existing private `JsonOptions`. `JsonException` / `IOException` / `UnauthorizedAccessException` → return `ImportResult(0, 0, 0, ["<file>: <message>"])`.
  2. Refuse `SchemaVersion > CurrentSchemaVersion` with a "schema version N not supported (max M)" warning.
  3. Refuse on `SnapshotCompatibilityChecker.Check(snapshot.KeyboardId, expectedKeyboard) == SnapshotCompatibility.None` → `RefusedWrongKeyboard = 1`. `Compatibility.Firmware` (same VID/PID, different UID) is **not** refused — the velvet rule is "warning handled at restore time, not import time".
  4. Skip on `File.Exists(targetPath)` → `SkippedDuplicates = 1`. Target name is `Path.GetFileName(sourceFilePath)`.
  5. On success, **re-serialize** the loaded `KeymapSnapshot` to the target rather than `File.Copy`. Round-tripping through `JsonSerializer` normalizes the on-disk format (no smuggled comments, BOMs, or extra fields) so future schema migrations only have to deal with shapes the app itself has produced.
  6. Logs `DiagnosticLog.Info("Snapshot", "Imported snapshot: <fileName>")` on success.

### 194. MainWindowViewModel — FirstConnect capture + manual-capture command

**Modified:** `src/SvalboardLayerViz.App/ViewModels/MainWindowViewModel.cs`

- New `private async Task TryCaptureFirstConnectSnapshotAsync()` — called from `TryConnectAsync` immediately after the `Status_ConnectedFormat` status update and before any matrix/LED polling kicks in. Calls `_snapshotService.ListAsync(keyboardId)`; if the count is `0` for this keyboard, captures a `SnapshotReason.FirstConnect` snapshot. **Best-effort by design** — wrapped in try/catch with a `DiagnosticLog.Warn` on failure. Unlike pre-save capture (which is load-bearing for partial-failure recovery), a missing first-connect snapshot just means the user has no "factory restore" point; it must never block the connect.
- `ListAsync(keyboardId)` filters via `SnapshotCompatibilityChecker`, so it already includes `Firmware`-level matches. Net effect: a user reflashing firmware on the same physical board does **not** get a second FirstConnect snapshot, which is the right behavior — the original capture remains valid as the pre-reflash baseline.
- New `[RelayCommand] private async Task CaptureManualSnapshot(string? userLabel)` — captures a `SnapshotReason.Manual` snapshot of the current device keymap (`GetDeviceKeymap()`) with the user-supplied label threaded through. **No UI binding yet** — XAML wiring lands in S3 (camera-icon button in the edit-mode sub-toolbar). The command exists on the VM so S2 can write tests against it without waiting for the AXAML.
- Existing pre/post-save callers in `SaveEdit` updated to use `ct: ct` named-arg syntax now that `CaptureAsync` has an optional `userLabel` parameter sitting between the keymap and the cancellation token.

### 195. SnapshotServiceTests — UserLabel + Import coverage

**Modified:** `src/SvalboardLayerViz.Tests/History/SnapshotServiceTests.cs`

- Seven new test cases, mirroring the velvet plan §1281–1286 import matrix plus a `UserLabel` round-trip:
  - `CaptureAsync_WithUserLabel_Persists` — capture with `userLabel: "before refactor"`, list, load, assert `UserLabel` round-trips. Implicitly proves the schema add is non-breaking.
  - `ImportAsync_ValidMatchingKeyboard_Imports` — capture into a separate temp dir via a second `SnapshotService` instance, import into `_tempDir`, assert `Imported = 1` and that `LoadAsync` round-trips `CapturedAt` + `Keycodes`. The two-service pattern mimics how a user moves a JSON between machines.
  - `ImportAsync_WrongKeyboard_Refused` — source built with `otherKb` (different VID/PID), import expecting `TestKbId` → `RefusedWrongKeyboard = 1`, no file copied.
  - `ImportAsync_FirmwareMismatch_ImportsCleanly` — same VID/PID, different UID → `Imported = 1`. Locks in the velvet rule that firmware-mismatch warnings happen at restore time, not import time.
  - `ImportAsync_DuplicateFilename_Skipped` — pre-creates a sentinel file at the target name with body `"SENTINEL"`, then asserts after import that the body is unchanged. Catches both the skip count and the no-overwrite invariant.
  - `ImportAsync_FutureSchemaVersion_Refused` — hand-crafted JSON with `"schemaVersion": 2`, otherwise valid enough to deserialize. Asserts a single warning containing `"schema version"`.
  - `ImportAsync_MalformedJson_Refused` — writes `"{ this is not json"` to a `.json` file, asserts a single warning and that no exception escapes the call.
- Helper `MakeExportDir()` creates a sibling temp dir for the source-file side of import scenarios; each test cleans it up in a `try/finally` so a failure doesn't leak temp dirs across runs.
