# Changes — 15-04-26 (Session 3)

## Phase 4d — Polish & Bugfixes

Post-Phase-4d UX cleanup plus two stale-data bugs exposed by the new combo/tap-dance features.

### 308. Combo inputs restricted to Basic category

**Modified:** `src/SvalboardLayerViz.App/ViewModels/ComboEditorViewModel.cs`

- `InputCategories` now contains `PickerCategory.Basic` only (removed `Modifier`). Chording modifiers as combo inputs doesn't map to a useful firmware behavior — you can just chord them normally.
- `OutputCategories` unchanged (still includes Modifier + Layer/Media/Mouse/Macro/Custom/Advanced). Modifier output is a legitimate use case.

### 309. Snapshot diff dialog surfaces combo/tap-dance/macro changes

**Modified:** `src/SvalboardLayerViz.App/ViewModels/SnapshotDiffDialogViewModel.cs`

- `ChangeCount` previously counted only keymap `Diffs`. Restore already applied combo/TD/macro deltas, but the UI banner showed "No changes" whenever only those differed — restore looked broken.
- Added `AuxChangeCount` + fold-in pass after the keymap diff build: per-index byte compare for `snapshot.Combos` / `snapshot.TapDances`, single compare for `snapshot.MacroBuffer`. Emits `DiffLineViewModel` entries (`Combo C{i}: modified`, `Tap Dance TD{i}: modified`, `Macros: modified`) with sentinel Layer/Row/Col = -1 so they render in the change list without claiming a board position.
- `HasChanges` now true whenever any keymap OR aux change exists.

### 310. Post-save reload refreshes combo + tap-dance tables

**Modified:** `src/SvalboardLayerViz.App/ViewModels/MainWindowViewModel.cs`

- `ReloadKeymapFromDeviceAsync` rebuilt `KeyboardConfig` with fresh `Layers`/`QmkSettings`/`Macros` but left `Combos`/`TapDances` pointing at pre-save bytes. Every downstream consumer (`GetDeviceCombos()`, pre-save + post-save snapshots, diff dialog) saw stale data until the user hit the main-bar refresh button (which goes through a full `KeymapLoader`).
- Fix: re-read the dynamic-entry tables inside `ReloadKeymapFromDeviceAsync` — `GetDynamicEntryCounts` + per-index `GetComboEntry`/`GetTapDanceEntry` (≤32 entries each, wrapped in a single `Task.Run`). Include both in the `KeyboardConfig with { ... }` update.
- Mirrors the existing macro/QMK-settings reload pattern. Cost: up to 64 small HID reads, comparable to the keymap reload already happening here.
