# Changes — 17-04-26

## God-VM decomposition round 2 + hostile-review ship-readiness pass

Continuation of yesterday's review round. `MainWindowViewModel` had shrunk to 1939 lines via the earlier extractions but still owned device-connect orchestration, save-flow sequencing, post-save device re-fetch, matrix→layer resolution, and partial-save reconciliation. This session pulled every one of those concerns out into pure Core services, collapsed three copy-paste editor VMs onto a shared base, unified the keycode encoder/decoder pair, and tightened the Keycode test suite. `MainWindowViewModel` is now 1753 lines. 1157 tests passing.

Final act of the day: five parallel hostile-review agents run against the remaining surface area (protocol/threading, edit session/codecs, persistence, view layer, test honesty) — their findings distilled into a Tier-1..4 ship-readiness plan at `~/.claude/plans/next-session-rework.md`. No fixes from that plan are in this commit; next session picks up on Tier 1.

### 330. `DeviceSession` — connect flow lifted to Core

**Added:** `src/SvalboardLayerViz.Core/Device/DeviceSession.cs`
**Modified:** `src/SvalboardLayerViz.App/ViewModels/MainWindowViewModel.cs`

- Discovery, preferred-device pick (Svalboard "lightly" prefix), keymap load, tapping-term probe, LED-capability probe now live behind a single `DeviceSession.Connect(deviceService, protocol, keycodeService, settings)` static factory returning a hydrated `DeviceSession(Device, Config, TappingTerm, LedPollSupported)` record.
- `MainWindowViewModel.TryConnectAsync` drops from ~60 lines of interleaved I/O + UI state updates to a `Task.Run(() => DeviceSession.Connect(...))` call followed by property assignment. The private `PickPreferredDevice` helper in the VM is deleted.
- Rationale: keep all protocol chatter off the UI thread in one place; make the hydrated-state shape explicit as a record instead of a 4-tuple of side-effects.

### 331. `SaveFlow` — save pipeline orchestration out of the VM

**Added:** `src/SvalboardLayerViz.Core/Keymap/SaveFlow.cs`
**Modified:** `src/SvalboardLayerViz.App/ViewModels/MainWindowViewModel.cs`

- Pre-save snapshot → execute writes → reload → post-save snapshot → background prune → optional re-lock was a ~130-line block in `SaveEdit`. Moved to `SaveFlow.RunAsync(Context, ct)` returning an `Outcome(Execution, Intended)` record. `SaveFlow.ReLockAsync(protocol)` swallows + logs re-lock failures in one place.
- `Context` record carries the dependencies the VM used to capture in closures: `Protocol`, `SnapshotService`, `EditSession`, `KeyboardId`, `DeviceName`, `KeepFirstConnectDays`, `CurrentDeviceSnapshot` (Func), `ReloadAsync` (Func). `SaveEdit` shrinks to ~35 lines — preflight confirmation, macro-buffer-overflow guard, `SaveFlow.RunAsync`, `ApplySaveResult`.
- Retained in VM (deliberately): safety-warning confirmation, macro-buffer overflow guard, status/dirty bookkeeping, `ApplySaveResult`, partial-session rebuild — all touch UI state directly.

### 332. `DeviceRefreshService` — post-save reload consolidated

**Added:** `src/SvalboardLayerViz.Core/Keymap/DeviceRefreshService.cs`
**Modified:** `src/SvalboardLayerViz.App/ViewModels/MainWindowViewModel.cs`

- `ReloadKeymapFromDeviceAsync` used to fetch keymap + QMK settings + macros + combos + tap-dances inline. Now delegates to `DeviceRefreshService.Fetch(protocol, currentConfig, knownMacroBuffer, skipMacroReload)` returning `Result(Keymap, QmkSettings, Macros, Combos, TapDances)`. ~60 lines removed from the VM.
- The `knownMacroBuffer` shortcut (skip the slow chunked USB re-read right after a save that wrote the buffer) and `skipMacroReload` (no macros changed) flags are now properties of the service API instead of flags threaded through VM state. Private `FetchMacros` helper keeps the fallback chain (known buffer → re-read → fall back to existing on failure).

### 333. `DeviceSnapshot` — the capture-shape, with a factory on `KeyboardConfig`

**Added:** `src/SvalboardLayerViz.Core/History/DeviceSnapshot.cs`
**Modified:** `src/SvalboardLayerViz.App/ViewModels/MainWindowViewModel.cs`

- `ISnapshotService.CaptureAsync` takes 4 positional parameters (keymap + macroBuffer + combos + tapDances). Callers kept assembling them inline — the VM had four separate methods (`GetDeviceKeymap`, `GetDeviceMacroBuffer`, `GetDeviceCombos`, `GetDeviceTapDances`) plus in-line construction at every capture site.
- Introduced `DeviceSnapshot(Keymap, MacroBuffer?, Combos?, TapDances?)` record with a `DeviceSnapshot.From(KeyboardConfig)` factory. An extension method `CaptureAsync(this service, reason, id, name, snapshot, ...)` accepts the record directly. The four getter methods collapse to `CurrentDeviceSnapshot()` + a thin `GetDeviceSnapshotForDiff()` that gates on connected state.
- Net: four getters + three `*ForDiff` siblings → one record, one factory, one public diff accessor. Capture call-sites read as single statements.

### 334. `LayerSwitchService` — auto-layer-switch machine leaves the VM

**Added:** `src/SvalboardLayerViz.Core/Keymap/LayerSwitchService.cs`
**Modified:** `src/SvalboardLayerViz.App/ViewModels/MainWindowViewModel.cs`

- Matrix→active-layer resolution (momentary/toggle key caches, rising-edge toggle detection, hold-threshold filtering, previous-matrix snapshotting) was ~130 lines of VM code plus five instance fields. Moved to `LayerSwitchService`: `BuildCache(baseLayer)` populates momentary/toggle dicts from layer-0; `Reset()` clears everything (disconnect); `ResetRuntimeState()` clears only the transient state (cache stays, used on Live-Highlighting toggle); `ResolveTargetLayer(state, nowTicks, holdThresholdMs)` returns the highest active layer.
- VM now just holds a `LayerSwitchService` and forwards the matrix callback. Testable without Avalonia. Per-loop bounds checks (added yesterday for matrix-size-swap robustness) travelled with the logic, so the crash fix from entry 318 is preserved.

### 335. `SaveReconciliation` — partial-save bucket logic extracted

**Added:** `src/SvalboardLayerViz.Core/Keymap/SaveReconciliation.cs`
**Modified:** `src/SvalboardLayerViz.App/ViewModels/MainWindowViewModel.cs`

- `BuildPartialResult` in the VM walked the 3-D `intended`/`baseline`/`device` tensors to bucket every cell into Applied / StillPending / Diverged. Logic now in `SaveReconciliation.Reconcile(device, baseline, intended) → Result(Applied, StillPending, Diverged)`. VM does the call, uses the result to rebuild the edit session, and updates status.
- Single-purpose pure function, directly unit-testable. The three-way truth table (`want == was` skip, `have == want` applied, `have == was` still-pending, otherwise diverged) is spelled out in one place now instead of interleaved with VM state manipulation.

### 336. `SlotListEditorViewModel<TRow>` — base class for three copy-paste editors

**Added:** `src/SvalboardLayerViz.App/ViewModels/SlotListEditorViewModel.cs`
**Modified:** `src/SvalboardLayerViz.App/ViewModels/ComboEditorViewModel.cs`, `TapDanceEditorViewModel.cs`

- Combo, tap-dance (and in the future, any new dynamic-feature editor) shared a shape: a fixed-size `Rows` collection of slot-row VMs, `SelectedRow`, `Close` command, `RequestKeyPick` delegate, and a capacity/used/usage-label triple. Three separate almost-identical implementations.
- Common scaffolding now in `SlotListEditorViewModel<TRow> where TRow : class, ISlotEditorRow`. `ISlotEditorRow` exposes `IsEmpty` so the base can compute `UsedCount` without knowing row specifics. Subclasses supply `UsageLabelKey` and populate `Rows` in their ctor; `RaiseUsageChanged()` notifies the usage-label triple when a row edit affects occupancy.
- `ComboEditorViewModel` and `TapDanceEditorViewModel` now inherit this base and shed ~25 lines each of repeated boilerplate. Macro editor left alone — its row model is different enough (variable-length action list per slot, buffer-size tracking) that forcing it through this shape would cost more than it saves.

### 337. `KeycodeCodec.cs` — encoder and decoder unified

**Added:** `src/SvalboardLayerViz.Core/Keymap/KeycodeCodec.cs`
**Deleted:** `src/SvalboardLayerViz.Core/Keymap/KeycodeDecoder.cs`, `KeycodeEncoder.cs`

- Previous round (entry 324) extracted shared range constants to `KeycodeRanges` so encode/decode couldn't drift on the magic numbers. But the two operations themselves still lived in separate files — perfect mirror image, changed together every time. Same-file now forces side-by-side diffs.
- Public API unchanged: `KeycodeDecoder.Decode(ushort) → KeycodeDescriptor` and `KeycodeEncoder.Encode(KeycodeDescriptor) → ushort` are still the two static entry points; they're just defined back-to-back in one file named for what they are jointly.

### 338. Keycode test suite — Facts → Theories

**Modified:** `src/SvalboardLayerViz.Tests/Keymap/KeycodeServiceTests.cs`, `KeycodeDecoderTests.cs`, `KeycodeEncoderTests.cs`

- Previously 17 separate `[Fact]` tests across the three files that differed only in a keycode constant + expected label (one Fact per layer-function opcode: TO/MO/DF/TG/OSL/TT, one per ModTap mod combination, one per LayerTap layer, etc.). Each was a 4-line method boilerplate around a single assertion.
- Consolidated into 5 `[Theory]` methods with `[InlineData]` rows. Net: identical coverage, ~60 fewer lines of test scaffolding, and adding a new keycode row is one line instead of one method.
- Deliberately scoped: per-letter A–Z basic-keycode Facts (~26 of them) left alone for now — they share no logic beyond the label lookup and converting them gains less than converting the range-based families did. Diminishing returns flagged in next-session plan (Tier 3).
